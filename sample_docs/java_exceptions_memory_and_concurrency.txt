# Java Exceptions, Memory Management, and Concurrency Guide

## 1. NullPointerException (NPE) Root Causes and Mitigation
`java.lang.NullPointerException` occurs when an application attempts to use an object reference that has the value `null`:
- Invoking a method from a `null` object.
- Accessing or modifying a field of a `null` object.
- Taking the length of `null` as if it were an array.
- Accessing or modifying the slots of `null` as if it were an array.
- Throwing `null` as if it were a `Throwable` value.
- Unboxing a `null` wrapper type (e.g., `Integer num = null; int val = num;`).

### Best Practices to Prevent NPE:
1. Use `Optional<T>` for return types that might be absent:
   ```java
   public Optional<User> findUserById(String id) {
       return Optional.ofNullable(userRepository.get(id));
   }
   
   // Calling side:
   findUserById("123").ifPresent(user -> System.out.println(user.getName()));
   ```
2. Put literals first in `.equals()` comparisons:
   ```java
   // DANGEROUS: Throws NPE if inputStatus is null
   if (inputStatus.equals("ACTIVE")) { ... }
   
   // SAFE: "ACTIVE" is never null
   if ("ACTIVE".equals(inputStatus)) { ... }
   ```
3. Use `Objects.requireNonNull(arg, "arg must not be null")` in constructors.

## 2. String Comparison: `==` vs `.equals()`
In Java, the `==` operator compares **object memory references**, while the `.equals()` method compares **content equality**:
```java
String s1 = "Hello";
String s2 = new String("Hello");

System.out.println(s1 == s2);      // FALSE: Different memory locations in Heap vs String Pool
System.out.println(s1.equals(s2));  // TRUE: Identical character sequences
```
- String Pool Optimization: String literals (e.g., `"Hello"`) are reused from the JVM String Intern Pool. However, strings created via `new String()`, user input, or network streams reside in distinct heap memory.
- Rule: **Always** use `.equals()` or `Objects.equals(a, b)` for String and object comparisons.

## 3. ConcurrentModificationException
Thrown when an object is concurrently modified while it is being iterated over using an iterator or enhanced `for` loop:
```java
// BUG: Modifying collection while iterating with enhanced for-loop
List<String> names = new ArrayList<>(List.of("Alice", "Bob", "Charlie"));
for (String name : names) {
    if (name.startsWith("A")) {
        names.remove(name); // Throws ConcurrentModificationException!
    }
}
```
### Safe Solutions:
1. Use `Iterator.remove()` explicitly:
   ```java
   Iterator<String> it = names.iterator();
   while (it.hasNext()) {
       if (it.next().startsWith("A")) {
           it.remove(); // Thread-safe and state-synchronized removal
       }
   }
   ```
2. Use modern `Collection.removeIf()` (Java 8+):
   ```java
   names.removeIf(name -> name.startsWith("A"));
   ```
3. For multi-threaded environments, use concurrent collections:
   - `CopyOnWriteArrayList` for read-heavy lists.
   - `ConcurrentHashMap` for lock-free multi-threaded maps.

## 4. Resource Leaks and `try-with-resources`
Unclosed file streams, database connections (`Connection`, `Statement`, `ResultSet`), or network sockets lead to file descriptor exhaustion and connection pool starvation.

### Fix: Automated Resource Management (Java 7+)
Any class implementing `java.lang.AutoCloseable` can be wrapped in a `try-with-resources` block, guaranteeing closure even if an exception is thrown:
```java
try (Connection conn = dataSource.getConnection();
     PreparedStatement stmt = conn.prepareStatement("SELECT * FROM users WHERE id = ?");
     ResultSet rs = stmt.executeQuery()) {
    while (rs.next()) {
        processRow(rs);
    }
} // Automatically closes rs, stmt, and returns conn to pool!
```

## 5. ArrayIndexOutOfBoundsException & StringIndexOutOfBoundsException
In Java, array and list indices are strictly zero-based, spanning from `0` to `size - 1`:
```java
// Common off-by-one error:
int[] data = new int[5]; // Valid indices: 0, 1, 2, 3, 4
for (int i = 0; i <= data.length; i++) { // BUG: data.length is 5!
    System.out.println(data[i]); // Throws ArrayIndexOutOfBoundsException at i=5
}

// FIX: Use strict inequality (<)
for (int i = 0; i < data.length; i++) {
    System.out.println(data[i]);
}
```
